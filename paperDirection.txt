======================================================================
1. THE PAPER IN ONE PARAGRAPH
======================================================================

AI systems increasingly need to decide which of their own outputs deserve extra scrutiny because expensive verification cannot be applied to everything. Confidence is an obvious signal for making that decision. D1 causally intervenes on this feedback loop by keeping a question and the model's frozen answer fixed while changing only the confidence value shown back to the model before it decides whether to request an independent external verification. The confidence intervention strongly changes the verification rate: on fresh preregistered MMLU-Pro data, displayed 0.70 versus 0.99 moves GPT's verification rate by 50.2 percentage points and Claude's by 35.4 points. But the deeper result is that allowing the displayed score to create a different ranking of which outputs deserve verification adds essentially no held-out predictive value: the richer condition-sensitive model improves held-out log loss by only 0.0008 for GPT and effectively 0.0000 for Claude. The dominant role of counterfactual confidence feedback is therefore to control verification coverage rather than to rewrite the allocation ranking. In practical terms, changing the confidence scalar can tune how much oversight occurs, but if the system is prioritizing the wrong outputs, changing the scalar alone is unlikely to fix that ranking.


======================================================================
2. PRECISELY WHAT THE SYSTEM IS DOING
======================================================================

The phrase "self-verification" can be misleading and must be used carefully.

The target model is NOT itself performing the independent verification.

The pipeline is:

STAGE 1 — ANSWER
The model answers a question.

STAGE 2 — CONFIDENCE
The model reports a probability that its frozen answer is correct.

STAGE 3 — VERIFICATION-REQUEST DECISION
The model chooses one of two actions:

USE_UNVERIFIED
    Use or deliver the frozen answer without an independent check.

VERIFY_FIRST
    Send the frozen answer to an independent verifier before it is used.

The target model therefore behaves as a ROUTER, TRIAGE POLICY, or SELECTIVE-OVERSIGHT CONTROLLER.

Its job is:

    decide whether this already-produced output deserves expensive
    additional scrutiny.

The external verifier does the actual verification.

This distinction matters for the real-world interpretation.

The paper is not asking:

    "Can GPT solve the same question twice?"

It is asking:

    "Can an AI system decide when one of its own outputs should trigger
    an additional verification resource?"

That resource could correspond in a real system to:

- a human reviewer;
- a stronger model;
- retrieval;
- web search;
- a test suite;
- a specialized checker;
- another agent;
- additional compute;
- a tool call;
- abstention / deferral.

The experiment uses an abstract perfect independent verifier to isolate the routing decision itself.


======================================================================
3. THE REAL SYSTEMS PROBLEM
======================================================================

The motivating systems problem is selective oversight under limited resources.

Suppose an AI produces 100,000 outputs.

It may be impossible or wasteful to independently verify all 100,000.

So the system needs to decide:

    which outputs deserve expensive follow-up?

This creates two different technical problems.

PROBLEM A — COVERAGE / BUDGET

How many outputs should receive verification?

Examples:
- 5%
- 20%
- 50%

This is the quantity of oversight.


PROBLEM B — RANKING / ALLOCATION

Which outputs should receive that limited verification budget?

If only 20% can be checked, the ideal system spends that 20% on the outputs most likely to be wrong or harmful.

This is the quality of allocation.


These two problems are easy to conflate.

A system may be excellent at controlling:

    "verify 20%"

while being poor at:

    "make sure the right 20% are verified."


D1's final contribution is about what displayed confidence controls inside this selective-oversight problem.


======================================================================
4. WHAT "RANKING" MEANS
======================================================================

Ranking does NOT mean the answer choices A/B/C/D/E inside one multiple-choice question.

Ranking means an ordering across DIFFERENT already-answered questions / outputs.

Imagine the model produced answers to five unrelated questions:

Output 1
Output 2
Output 3
Output 4
Output 5

The model may implicitly behave as though these are ordered:

1. Output 3 — most worth verifying
2. Output 1
3. Output 5
4. Output 2
5. Output 4 — least worth verifying

Now suppose displayed confidence changes.

At lower displayed confidence, the model may request external verification for:

    Output 3
    Output 1
    Output 5
    Output 2

At higher displayed confidence, it may request verification only for:

    Output 3

The amount of verification changed dramatically.

But the ordering remained broadly stable.

This is the intuition behind ranking invariance.

The model is moving a cutoff over a largely shared ordering rather than constructing a brand-new prioritization policy at each confidence value.


======================================================================
5. WHAT "RANKING INVARIANCE" DOES AND DOES NOT MEAN
======================================================================

The paper must use "ranking invariance" carefully.

It does NOT mean:

- every item has exactly the same numerical rank at every score;
- no stochastic reversals ever occur;
- AUROC is numerically identical at every score;
- the system is deterministic;
- score has literally zero influence on any item-specific behavior.

The repeated-generation correlations are substantial but not perfect.

The correct claim is softer and more defensible:

    displayed confidence predominantly changes verification coverage,
    while explicit score-dependent reprioritization contributes essentially
    no additional held-out predictive value.

Another acceptable formulation:

    a shared item-ranking tendency plus condition-specific thresholds is
    sufficient to explain the fresh GPT/Claude data relative to the
    preregistered richer alternative.

The phrase "largely invariant" therefore means:

    the main systematic effect is on the cutoff / coverage,
    not on rebuilding the prioritization function.


======================================================================
6. THE KEY CAUSAL INTERVENTION
======================================================================

Natural confidence is confounded with item difficulty.

Suppose:

- difficult questions produce lower confidence;
- difficult questions are also more likely to be verified.

Then observing:

    low confidence -> more verification

does not prove that confidence itself caused the verification decision.

The same underlying difficulty could drive both.

D1 solves this with a fixed-item counterfactual intervention.

For a given question:

- keep the question fixed;
- keep the Stage-1 answer fixed;
- freeze the answer so it cannot change;
- change only the displayed confidence value;
- ask whether the answer should be sent to the external verifier.

Example:

Same question.
Same frozen answer.

Condition A:
"The AI previously estimated a 0.70 probability that this frozen answer is correct."

Condition B:
"...0.90 probability..."

Condition C:
"...0.99 probability..."

This allows a causal statement about the displayed scalar itself.

The intervention asks:

    If everything about the underlying output stays fixed, what part of
    the verification policy changes when the displayed confidence changes?


======================================================================
7. THE PAPER'S FINAL HIGH-LEVEL ANSWER
======================================================================

The evidence now supports:

    displayed confidence strongly changes HOW MUCH verification is requested,
    but changes much less about WHICH outputs are prioritized.

On prospectively confirmed MMLU-Pro data:

GPT:
    displayed 0.70 -> 0.99 changes verification by 50.2 percentage points
    95% CI [45.8, 54.6]

Claude:
    displayed 0.70 -> 0.99 changes verification by 35.4 percentage points
    95% CI [31.2, 39.6]

At the same time:

GPT:
    richer score-specific reprioritization model held-out improvement
    = 0.0008
    95% CI [-0.0011, 0.0026]

Claude:
    richer score-specific reprioritization model held-out improvement
    ≈ 0.0000
    95% CI [-0.0009, 0.0008]

Both passed the preregistered invariance criterion.

The result is therefore not merely:

    confidence affects verification.

The stronger result is:

    confidence has a very large causal effect on verification COVERAGE,
    while a much more complicated hypothesis in which each score condition
    creates a new prioritization rule provides essentially no additional
    held-out predictive value.


======================================================================
8. WHY THAT RESULT IS INTERESTING
======================================================================

Confidence is an intuitive control signal for selective oversight.

A system builder may naturally think:

    "If I can manipulate, calibrate, or expose confidence differently,
    maybe I can improve the routing policy."

D1 shows an important limitation.

Changing displayed confidence can be highly effective at deciding:

    HOW DEEP DOWN THE EXISTING RANKING TO VERIFY.

But it is a weak lever for deciding:

    WHAT THE RANKING SHOULD BE.

In practical terms:

If the system is already prioritizing the right outputs but verifying too many or too few:
    adjusting the confidence-driven threshold may help.

If the system is prioritizing the wrong outputs:
    changing the displayed confidence alone is unlikely to solve that.

The system needs a better ranking / risk signal.


======================================================================
9. WHY THIS IS NOT "JUST CONFIDENCE AFFECTS ABSTENTION"
======================================================================

A weak framing would be:

    "Confidence affects whether models escalate."

That overlaps strongly with existing abstention, selective prediction, and escalation work.

The stronger paper is about a more specific causal question.

D1 asks:

    if we counterfactually replace the confidence value shown for the exact
    same frozen output, does that intervention improve/change the allocation
    of verification, or mostly move the verification rate?

The answer is:

    mostly the verification rate.

The novelty therefore lies in the combination of:

1. fixed-item counterfactual manipulation;
2. the model's own confidence-style signal being fed back into its routing decision;
3. explicit separation of coverage change from ranking change;
4. prospective evidence that the richer score-specific ranking story buys essentially nothing.

12. STUDY 1 — CAUSALLY ISOLATING THE DISPLAYED SCORE
======================================================================

Study 1 held:

- question fixed;
- Stage-1 answer fixed;
- historical confidence fixed in the background;

and changed only the confidence number DISPLAYED at Stage 3.

Under explicit numerical costs, GPT produced an extreme threshold response.

At L=10:

displayed 0.89:
    essentially always VERIFY

displayed 0.91:
    essentially always USE


At L=20:

displayed 0.94:
    essentially always VERIFY

displayed 0.96:
    essentially always USE


This is a crucial result because it eliminates a basic confound.

The difference is not merely:

    naturally low-confidence questions are harder.

The same frozen item changes action when only the displayed scalar changes.

CONTRIBUTION TO THE FINAL NARRATIVE:

    The score is a causal control input.

14. CHECKPOINT A — CALIBRATION EXPLAINS MUCH OF THE ORIGINAL "HARM"
======================================================================

The original workshop-style interpretation focused on:

    visible confidence sometimes caused fewer wrong answers to be verified.

An overly strong narrative would be:

    "Showing confidence damages the model's judgment."

Checkpoint A showed why this is not the right interpretation.

GPT was overconfident.

If:

- q is overconfident;
- the model follows q faithfully;
- the verification threshold depends on q;

then visible confidence can move the system to a low-verification operating point.

That can increase unchecked errors without any need to claim:

    the model lost its ability to rank risky outputs.

CONTRIBUTION TO THE FINAL NARRATIVE:

Checkpoint A separates:

CALIBRATION
    Are the probability values numerically accurate?

COVERAGE CONTROL
    Does the scalar move how much verification is requested?

RANKING QUALITY
    Are the right outputs prioritized?

This conceptual separation becomes central to the final paper.

16. TASKS 005B / 005C — DIFFICULTY DESTROYS THE "SECRET KNOWLEDGE" INTERPRETATION
======================================================================

At a fixed displayed score, Claude appeared to verify wrong answers more frequently than correct ones.

That initially suggested:

    perhaps Claude retained richer answer-specific information than q expressed.

Task 005B tested a simpler alternative:

    difficult items are both more likely to be wrong
    and more likely to be verified.

Difficulty was estimated using OTHER models' correctness, excluding the target model.

For GPT:
- Claude + Gemini + Grok.

For Claude:
- GPT + Gemini + Grok.

After controlling for difficulty:

- most of Claude's fixed-score wrong/correct signal disappeared.

Task 005C extended this to the q1+q2 residual.

After q1 + q2 + difficulty:

- Claude's residual was largely explained;
- GPT retained only a small leftover.

CONTRIBUTION TO THE FINAL NARRATIVE:

These analyses are scientifically valuable because they REMOVE an attractive but unsupported mechanism claim.

They tell us not to write:

- "the model secretly knows it is wrong";
- "confidence suppresses hidden truth";
- "VERIFY accesses privileged internal correctness evidence."

Instead:

    verification behavior strongly tracks generic item risk / difficulty.

This is a major narrative cleanup.

18. TASK 007 — THE INTERMEDIATE BUDGET/PRIORITIZATION STORY
======================================================================

Task 007 initially suggested:

GPT:
    score shifts budget while preserving difficulty priority.

Claude:
    score may sharpen difficulty prioritization.

The switch-set analysis showed that as confidence rose, items retained in VERIFY tended to be harder than items dropped.

This was useful because it suggested:

    the score was changing coverage without obviously destroying item sensitivity.

But this was not yet the final story.

WHY NOT?

Because once VERIFY sets are mostly nested, harder items will naturally remain if:

- the underlying verification propensity correlates with difficulty;
- the score simply moves a threshold.

Also, probability-scale hard/easy gaps can appear to widen near different operating points even with a stable latent slope.

CONTRIBUTION TO THE FINAL NARRATIVE:

Task 007 was the bridge from "hidden uncertainty" to the more precise question:

    Is the score moving the threshold or changing the ranking?

19. TASK 008 — DISCOVERING THE FINAL HYPOTHESIS
======================================================================

Task 008 rigorously audited the threshold/ranking hypothesis on the exploratory N=100 qualitative grid.

It found multiple pieces of convergent evidence.

A. NEAR-NESTING

As displayed confidence rose:

- most transitions were VERIFY -> USE;
- USE -> VERIFY reversals were nearly absent.

This is expected under a moving threshold over a stable ordering.


B. CROSS-CONDITION ITEM PREDICTION

A shared item propensity learned from some score conditions predicted decisions under held-out score conditions well.

Held-out AUROCs were often around 0.7–0.94.

Interpretation:

    which items are treated as verification-worthy transfers across
    displayed confidence conditions.


C. RICHER INTERACTION MODELS ADDED LITTLE

Condition-sensitive models that allowed score-dependent reprioritization generally did not materially improve out-of-sample fit.


D. CLAUDE "SHARPENING" DID NOT NEED TO BE A DISTINCT BEHAVIORAL LAW

Once the analysis moved to the latent scale and judged models by out-of-sample prediction, the evidence did not require a separate "Claude sharpens" mechanism.


Task 008 decision:

    INVARIANCE_SUPPORTED_EXPLORATORY


CONTRIBUTION TO THE FINAL NARRATIVE:

Task 008 DISCOVERED the final candidate hypothesis.

But because it used the same development data from which the hypothesis emerged, it could not establish the final result.

That required Task 009.

22. TASK 009 H2 — THE CENTRAL RANKING-INVARIANCE TEST
======================================================================

This is the most important analysis for the final paper.

Two models were compared.


SHARED-RANKING MODEL

Conceptually:

    verification propensity =
        condition-specific threshold / intercept
        +
        shared item tendency.

Meaning:

- different confidence values can make verification globally more or less likely;
- the underlying item priority structure is shared.


CONDITION-SENSITIVE MODEL

This richer model additionally allows confidence condition to reshape prioritization.


The preregistered metric was:

    how much better does the richer model predict held-out data?


Results:

GPT:
    improvement = 0.0008
    95% CI [-0.0011, 0.0026]

Claude:
    improvement ≈ 0.0000
    95% CI [-0.0009, 0.0008]

Both passed the preregistered invariance criterion.


WHY THIS MATTERS:

This is the final paper's strongest evidence that:

    the score's dominant role is moving coverage,
    not creating a new routing order.

The correct interpretation is not:

    "the rankings are exactly identical."

It is:

    "Once we allow the score to move the global verification rate,
    a richer score-dependent reprioritization hypothesis buys essentially
    no extra held-out predictive power."

That is the clean central result.

======================================================================
26. RISK-COVERAGE INTERPRETATION
======================================================================

Raw error catch naturally depends on coverage.

If one condition verifies 70% of outputs and another verifies 10%, the first will usually catch more errors simply because it checks more things.

So the paper must distinguish:

RAW CATCH
    how many errors were caught at the actual induced verification rate.

from

RANKING QUALITY
    how effectively errors are prioritized for a given verification budget.

This is one of the key corrections to the original workshop interpretation.

The final manuscript should repeatedly avoid phrases like:

    "condition X caught fewer errors, therefore its ranking got worse."

That inference is invalid when coverage differs.


======================================================================
27. REINTERPRETING THE ORIGINAL WORKSHOP RESULT
======================================================================

The original result could be summarized as:

    visible confidence made GPT leave more wrong answers unverified.

Earlier interpretation risk:

    showing confidence degraded the model's judgment.

Final interpretation:

    displayed confidence strongly changed the verification operating point;
    GPT's confidence was overconfident;
    faithfully following that scalar moved GPT toward lower coverage;
    lower coverage naturally leaves more errors unchecked.

The new paper therefore reframes the old finding:

OLD:
    confidence visibility harms verification quality.

NEW:
    confidence visibility changes verification quantity strongly;
    much of the apparent harm is an operating-point/calibration effect;
    score-dependent ranking degradation is not required to explain it.

This is a scientifically stronger interpretation because it separates mechanisms that the original paper conflated.

- risk-coverage curves;

The potentially novel empirical package is:

1. FIXED-ITEM COUNTERFACTUAL CONFIDENCE INTERVENTION

Same question.
Same frozen answer.
Different displayed confidence.

Confidence is a strong budget-control signal.

32. WHY AN ICLR REVIEWER SHOULD CARE
======================================================================

The broad relevance is selective resource allocation in AI systems.

Modern systems increasingly need to decide:

- when to defer;
- when to retrieve;
- when to call another model;
- when to ask a human;
- when to use more compute;
- when to run tools/tests.

Confidence is an obvious control signal for these decisions.

The paper reveals a specific limitation:

    confidence feedback can strongly tune the amount of oversight while
    doing little to alter the underlying prioritization.

That is useful because system builders can otherwise mistake:

    "we can control escalation rate"

for:

    "we can improve escalation quality."

Those are different.

The paper makes that distinction empirical and causal.

34. PRACTICAL EXAMPLE
======================================================================

Suppose an AI produces 1,000 answers.

A system can afford to independently verify only 100.

The model has an implicit ranking of which outputs seem most worth checking.

If the ranking is good:

    top 100 may contain many of the actual errors.

If the ranking is poor:

    top 100 may waste budget on safe outputs.

Now change displayed confidence.

D1 finds that this can strongly change whether the model sends:

    500 outputs
    300 outputs
    100 outputs
    50 outputs

to verification.

But it does not materially improve the score-specific ranking model.

Therefore:

    changing confidence can help choose the budget,
    but not necessarily improve the queue.

This is the practical message.

35. CALIBRATION VS COVERAGE VS RANKING
======================================================================

The paper should clearly separate three ideas.

CALIBRATION

Does 90% confidence correspond to roughly 90% correctness?


COVERAGE CONTROL

Does changing the displayed score change how often verification is requested?


RANKING QUALITY

For a fixed budget, are the most error-prone outputs prioritized?


A model can be:

- badly calibrated;
- strongly score-responsive;

    score-specific reprioritization adds essentially no predictive benefit.

This separation is central to the paper's intellectual clarity.

43. FINAL PAPER NARRATIVE — FULL VERSION
======================================================================

AI systems increasingly operate under selective oversight: they cannot afford to send every output to a human, stronger model, retrieval system, or external verifier. Confidence is an obvious signal for controlling those escalation decisions, but confidence can influence two very different parts of the system: how much verification occurs and which outputs receive it. D1 separates these effects causally. For the exact same frozen answer, we counterfactually change only the confidence score shown back to the model and observe whether it requests independent verification. The displayed score has a large causal effect on verification coverage, and the effect survives removing explicit numerical cost arithmetic. We then test whether the score also changes the allocation ranking. A preregistered prospective study on fresh GPT/Claude MMLU-Pro data finds that coverage shifts by 50.2 and 35.4 percentage points, yet a richer score-specific reprioritization model provides essentially no additional held-out predictive value over a shared-ranking model with condition-specific thresholds. Repeated generations show substantial, though imperfect, cross-condition item stability. The dominant role of counterfactual confidence feedback is therefore to move the verification operating point rather than to rewrite which outputs receive priority. This implies that confidence is useful for tuning the quantity of selective oversight, but improving routing quality requires improving the ranking signal itself.
