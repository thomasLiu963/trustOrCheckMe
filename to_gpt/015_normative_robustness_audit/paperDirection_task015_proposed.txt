0. PURPOSE OF THIS DOCUMENT
======================================================================

This document supersedes all earlier D1 paperDirection files.

The final paper is NOT primarily about:
- hidden uncertainty;
- whether the model “knows” when it is wrong;
- ranking invariance;
- finding a better routing algorithm;
- whether confidence is globally good or bad;
- whether one model/provider is safer than another.

The final paper is about:

    CONFIDENCE METADATA AS A CONTROL SURFACE
    FOR RESOURCE-BOUNDED LLM VERIFICATION.

The central systems question is:

    How much causal leverage does the confidence metadata shown to an LLM
    router have over external verification behavior and downstream error
    leakage when the generated output itself is held fixed?

The paper now has TWO complementary causal intervention families:

A. FIXED-SCORE STRESS TEST
   - same frozen output;
   - every item in a condition receives the same displayed confidence;
   - removes the scalar's within-condition item discrimination;
   - isolates the maximum behavioral leverage of displayed confidence level.

B. RANK-PRESERVING LEVEL SHIFT
   - same frozen output;
   - each item keeps its own q1 ordering;
   - q1 is shifted monotonically in logit space;
   - separates confidence LEVEL from the item ordering carried by q1.

The fixed-score stress test produces the sharpest downstream effects:

GPT MMLU-Pro:
    coverage: 58.4% -> 8.2%
    leakage: 2.0% -> 13.8%
    +11.8 erroneous outputs per 100 bypass checking

GPT LiveCodeBench:
    coverage: 62.9% -> 24.1%
    leakage: 10.8% -> 32.9%
    +22.0 erroneous programs per 100 bypass the hidden-test verifier

The rank-preserving intervention then answers the obvious validity objection:
does the effect survive if the scalar remains item-informative?

Yes, but attenuated.

GPT MMLU:
    coverage: 23.0% -> 6.8%
    leakage: 9.0% -> 15.0%
    +6.0pp leakage

GPT code:
    coverage: 26.2% -> 19.2%
    leakage: 31.1% -> 35.7%
    +4.5pp leakage

Thus:

    Item-level q1 information attenuates but does not remove
    confidence-level sensitivity.

The final scientific story is therefore:

    Confidence metadata is not passive metadata. It can act as a causal control
    surface for LLM verification routing.

    The largest oversight failures occur when the signal both shifts in level
    and loses item-discriminative structure, but systematic level shifts alone
    still move external verification and error leakage even when q1 ordering is
    preserved.

This is a behavioral systems paper, not a mechanism paper.

======================================================================
1. THE FINAL PAPER IN ONE PARAGRAPH
======================================================================

Large language models increasingly operate inside systems that selectively
spend expensive verification resources: human review, retrieval, stronger
models, additional computation, tools, executable tests, or other external
checks. Confidence is a natural routing signal, but the downstream policy can
itself give that signal large behavioral leverage. D1 isolates this leverage
causally by freezing the generated output and manipulating only the confidence
metadata shown before the model chooses USE_UNVERIFIED or VERIFY_FIRST.

On preregistered MMLU-Pro data, a fixed-score intervention from 0.70 to 0.99
changes verification coverage by 50.2 percentage points for GPT and 35.4
points for Claude. Post-hoc consequence analysis shows that GPT's unverified
error leakage rises from 2.0% to 13.8%.

We then move to frozen LiveCodeBench programs, where VERIFY_FIRST requests an
actual hidden test suite. GPT again shows a 38.8-point coverage shift, while
erroneous programs left unverified rise from 10.8% to 32.9%. Claude remains
near an always-verify ceiling.

Because a constant score removes the scalar's item discrimination, we run a
final preregistered rank-preserving intervention: each item's natural q1 is
shifted monotonically in logit space while preserving q1 ordering. The effect
attenuates but survives. GPT MMLU still shifts 16.2 points in coverage and 6.0
points in leakage; GPT code shifts 7.0 and 4.5 points respectively. Claude MMLU
also remains strongly level-sensitive, while Claude code stays near saturation.

The resulting systems lesson is:

    confidence quality, confidence item discrimination, and
    confidence-to-policy gain are separate properties.

A verification system should not only ask whether confidence is calibrated; it
should also measure how much external oversight the routing policy allows that
signal to control.

6. THE REAL SYSTEMS PROBLEM
======================================================================

Modern AI systems cannot afford to verify every output.

They selectively spend:
- human review;
- retrieval;
- a stronger model;
- extra reasoning;
- tool calls;
- code tests;
- specialized checkers;
- other agents.

Confidence is a natural signal for these routing decisions.

Most confidence work asks:

    Is the signal calibrated?
    Does it rank errors?
    Can it support abstention?

D1 asks a different systems question:

    HOW MUCH LEVERAGE DOES THE DOWNSTREAM POLICY GIVE THAT SIGNAL?

A system can fail along at least three distinct axes:

1. VALUE QUALITY
   Is the numerical confidence accurate?

2. ITEM DISCRIMINATION
   Does the signal still distinguish relatively risky from relatively safe
   outputs?

3. CONTROL GAIN
   How strongly does the downstream routing policy change external oversight
   as the confidence signal moves?

Task 012 showed the consequence of high control gain under the fixed-score
stress test.

Task 014 separates control gain from item discrimination.

======================================================================
7. THE CORE CAUSAL ESTIMAND
======================================================================

Natural confidence is confounded with item difficulty.

Hard items may naturally have:
- lower confidence;
- higher error rates;
- more verification.

Therefore observational correlations do not isolate confidence's causal role.

D1 uses fixed-output interventions.

For each item:

1. generate the output;
2. freeze the output;
3. obtain q1;
4. keep the problem and output fixed;
5. alter only the displayed confidence metadata;
6. ask the same router whether to USE_UNVERIFIED or VERIFY_FIRST.

Thus the causal estimand is:

    effect of displayed confidence metadata
    on verification-routing behavior
    for a fixed generated output.

The experiment does NOT identify:
- internal mechanism;
- activation-level confidence;
- provider-side hidden prompts;
- post-training cause;
- architecture-level universality.

======================================================================
8. TWO INTERVENTION FAMILIES
======================================================================

A. FIXED-SCORE STRESS TEST

Within each condition:
    every item receives the same score.

Advantages:
- maximal experimental control;
- easy causal interpretation;
- directly measures global policy responsiveness to the displayed level;
- yields very sharp resource/leakage consequences.

Limitation:
- score has no item-discriminative information within condition.

Interpretation:
    controlled stress test of confidence-to-policy leverage.

B. RANK-PRESERVING LEVEL SHIFT

Each item retains its own q1 ordering.

Advantages:
- keeps item-relative scalar structure intact;
- isolates systematic level shift more cleanly;
- directly answers the “constant score is artificial” objection.

Limitation:
- transformed values are still experimental;
- ordinary natural calibration drift need not follow the same curve;
- q1 ordering is only the ordering carried by the scalar, not all latent model
  uncertainty.

Interpretation:
    deployment-relevant robustness test of level sensitivity.

These two intervention families should be presented as complementary.

33. WHY THE “FAKE NUMBER” OBJECTION DOES NOT KILL THE PAPER
======================================================================

Reviewer attack:

    “You injected counterfactual numbers.”

Response:

Yes.

The fixed-score manipulation is intentionally a stress test that identifies the
causal leverage of displayed confidence metadata.

Three facts make the result meaningful:

1. the numerical range substantially overlaps natural q1;

40. ABSTRACT DIRECTION
======================================================================

Draft, not final manuscript wording:

Large language models increasingly decide when to spend costly external
verification resources, yet little is known about how much causal leverage
confidence metadata has over those routing decisions. We isolate this leverage
with fixed-output interventions: after a model produces an answer or program,
we freeze the output and vary only the confidence shown before it chooses
whether to request independent verification. On a preregistered study of 500
unseen MMLU-Pro questions, fixed displayed confidence from 0.70 to 0.99 changes
verification coverage by 50.2 percentage points for GPT and 35.4 points for
Claude. A post-hoc consequence analysis shows that GPT's erroneous outputs left
unverified rise by 11.8 points. We then study frozen LiveCodeBench programs,
where verification is an actual hidden test suite: GPT coverage shifts by 38.8
points and erroneous programs left unverified rise by 22.0 points, while
Claude remains near an always-verify ceiling. Because fixed scores remove
item-level discrimination, we run a final preregistered rank-preserving
intervention that monotonically shifts each item's natural confidence while
preserving q1 ordering. The effect attenuates but persists, with GPT leakage
rising by 6.0 points on MMLU and 4.5 points on code. These results show that
confidence level and item discrimination are distinct determinants of LLM
verification behavior, and that confidence metadata can act as a high-leverage
control surface for external oversight.
